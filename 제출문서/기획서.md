## 0. 핵심 메시지

**막히는 순간 규칙을 찾아 주고, 없으면 관리자·화주사까지 이어 주고, 답은 쌓인다.**

| 단계 | 앱이 하는 일 | 고객 근거 |
|---|---|---|
| 막히는 순간 규칙을 찾아 준다 | 파손 보고·작업지시·질문에서 그 화주사의 현행 지침서·계약서 조항을 근거와 함께 보여 줌 | 센터장: 처리 방법을 찾는 동안 작업자가 기다림 |
| 없으면 관리자·화주사까지 이어 준다 | 근거가 없으면 작업자 → 관리자 질문함 → (필요하면) 화주사 문의함 → 관리자가 작업자에게 전달 | 3차: "관리자가 먼저 확인… 어려우면 화주사에", "답도 관리자를 통해 작업자에게" |
| 답은 쌓인다 | 관리자가 전달한 답을 화주사별 센터 답변으로 저장, 확인 여부·날짜 표시, 지침서 개정 시 재확인 표시 | 3차: "같은 상황 답이면 남겨 두고 참고하는 건 괜찮습니다", "개정되면 다시 봐야" |

## 1. 누가, 언제, 왜 쓰나

| 사용자 | 역할 | 쓰는 장면 | 이 앱으로 바뀌는 것 |
|---|---|---|---|
| 작업자 장 씨 (냉장 구역) | WORKER | 입고 박스를 내리며 휴대폰으로 오늘 작업지시를 확인한다. 젖은 박스를 발견한다 | 종이 대신 휴대폰으로 지시를 보고 실제 수량을 입력해 완료한다. 파손은 사진을 찍어 **보고 버튼 하나**로 올리고, 그 화주사의 처리 방법을 바로 본다. 화면 맨 위에서 **최근 바뀐 지침**을 본다 |
| 관리자 최 과장 | MANAGER | 출고 작업 중 틈틈이 휴대폰·PC로 확인한다. 화주사별 지침을 찾는다 | "미확인 파손" 배지와 **30분 초과** 표시로 놓치지 않는다. 자주 찾는 3가지(파손 처리·냉장 온도·출고 순서)는 버튼 하나로 근거와 함께 답을 받는다 |
| 관리자 김 | MANAGER | 입고 예정을 등록하고, 수량 차이를 화주사에 알린다. 지침서 개정 메일을 받는다 | 예정·실제·차이 수량이 한 목록에 모인다. 새 지침서를 올리면 바뀐 조항이 표시되고 작업자에게도 알려진다 |
| 센터장 | ADMIN | 하루 현황과 파손 대응 상태를 본다 | 30분 넘게 확인 안 된 파손을 **알림으로 받고**, 수량 차이와 함께 한 화면에서 본다. 파손 사진·보고·확인 기록이 한곳에 남아 책임 판단 근거를 찾기 쉽다 |
| 화주사 담당자 | SHIPPER | 현재 재고가 궁금할 때 (문의 전화 1순위) | 자기 물건의 재고·입고 완료·수량 차이·파손 내용과 사진을 직접 본다. 다른 화주사 물건, 계약 내용, 내부 지침, 보관 위치, 처리 메모는 서버가 막는다 |

## 2. 대표 시나리오 (시연 순서)

인터뷰에서 확인한 실제 사고("파손 처리 방법을 찾는 동안 작업자가 1시간 기다림")를 처음부터 끝까지 다시 보여 줍니다.

1. 관리자 김: 신선마켓(냉장) 입고 예정 100박스 등록
2. 작업자 장 씨(휴대폰): 작업지시 확인 → 실제 98박스 입력·완료 → **예정 100 / 실제 98 / 차이 -2** 표시
3. 장 씨: 젖은 박스 사진으로 파손 보고 → **신선마켓 지침서의 파손 처리 조항이 근거와 함께 자동 첨부** → 기다리지 않고 바로 처리 방법 확인
4. 최 과장: "미확인 파손 1 · 보고 후 N분" 확인 처리 → 확인자·시각·**확인까지 걸린 시간** 기록, 처리 메모와 **화주사에 알린 시각** 기록. 30분이 넘은 건은 관리자 요약에 따로 표시되고 센터장에게 알림
5. 최 과장: 빠른 질문 "냉장 보관 온도" → 근거 조항과 함께 답. 지침서와 계약서가 다르면 두 내용을 나란히 보여 주고 "화주사와 확인 필요" 경고
6. 관리자 김: 한겨울푸드 지침서 v2 업로드 → **"24시간 → 6시간" 변경 조항 표시**, 같은 질문에 새 답, 작업자 화면 맨 위에 개정 알림
7. 화주사(신선마켓) 로그인: 자기 재고·입고·수량 차이·파손 사진만 보임(보관 위치·처리 메모는 안 보임). 다른 화주사 요청, 규칙 질문·문서 접근은 거부

|---|---|
| 고객의 실제 사고 | 인터뷰에서 확인한 최근 사고가 "파손 처리 방법 찾는 동안 현장이 멈춤"이므로 파손 입고 장면을 처음부터 끝까지 동작시키는 데 집중 |
| 시간 (13:00 마감) | 핵심 장면 하나를 끝까지 동작시키는 것이 기능 여러 개를 반쯤 만드는 것보다 낫다 |
| 고객이 "기준 없음"이라고 한 것 | 기한 없는 화주사의 통보 기한, 담당 배정, 지침서·계약서 우선순위(화주사와 확인), 보관 위치·처리 메모 공개, 책임 판단 추가 항목은 **시스템이 대신 정하지 않는다**. 기록과 확인 안내까지만 하고 판단은 사람에게 남김 |
| 심사 · 제작 30점 | "규칙과 권한이 지켜지는가", "고객 자료를 다루는 기능" → F4~F7을 오늘 범위에 넣음 |
| 고객의 확인 흐름 | 지침서에 없는 질문을 AI가 지어내면 위험하고, 고객은 "작업자 → 관리자 → 화주사" 순서로 확인한다고 답함(3차) → 그 순서를 앱 흐름으로 옮기고, 답을 쌓아 다음에 같은 질문에서 덜 막히게 함 |
| 심사 · 요구사항 20점 | 1·2차 인터뷰 답(30분·센터장 알림, 확인자·통보 시각 기록, 파손 필수 3항목, 자주 찾는 3가지, 작업자 읽음 확인, 화주사 공개 범위)을 기능에 그대로 연결 |
| 심사 · 기획 20점 | 미룬 기능마다 이유와 다음 단계를 남김 |
| 위험 | AI가 다른 화주사 지침을 섞어 답하거나 화주사에게 계약 내용이 보이면 큰 사고 → 검색을 선택한 화주사의 현행 문서로 제한하고, 화주사 계정은 문서 접근 자체를 차단 |
| 위험 · 현장 사용성 | 작업자가 휴대폰을 장갑 낀 채로, 창고 전 구역 인터넷에서 쓸 수 있는지는 확인되지 않음(장 씨 "확인해 본 적이 없습니다") → 도입 전 현장 시범 필요. 오늘은 큰 버튼·짧은 입력으로 설계 |

## 5. 가산점 제안 · 파손 보고에 지침 자동 첨부 (F8)

| 항목 | 내용 |
|---|---|
| 제안 | 작업자가 파손을 보고하는 순간, 그 화주사 지침서의 "파손 입고 시 처리" 조항을 AI가 찾아 근거와 함께 보고서에 붙인다. 작업자와 관리자가 같은 안내를 본다 |
| 고객이 직접 말하지 않았지만 필요한 근거 | ① 센터장: 최근 사고가 "처리 방법을 지침서에서 찾느라 시간이 걸렸고 작업자는 기다림" ② 장 씨: "작업을 멈추고 따로 두고 기다렸습니다" ③ 최 과장: 가장 자주 찾는 내용 1위가 파손 입고 처리 ④ 장 씨: 외국인 동료도 "화주사마다 처리 방법이 다르면 더 어렵다" |
| 기대 효과 | 관리자 확인(최대 30분)을 기다리지 않고 발견 즉시 처리 방법을 확인. 관리자는 지침서를 다시 찾지 않고 확인만 하면 됨 |
| 안전장치 | AI는 안내만 하고 처리 방향은 관리자가 확인해 정한다(관리자 김: "근무 중인 관리자가 처리 방향을 정합니다"). 근거 조항이 없으면 "지침서에 없음, 관리자 확인 필요"로 표시. 화주사 계정에는 이 내부 지침과 근거 원문을 보이지 않음 |

## 6. 성공 기준

- 지침서에 없는 질문이 작업자 → 관리자 → (화주사) → 작업자로 이어지고, 그 답이 확인 여부·날짜와 함께 저장되어 다음 질문에 보인다

- 위 시연 시나리오 1~7이 배포 주소에서 끊김 없이 동작한다
- 파손 보고부터 확인까지 걸린 시간이 기록되고, 30분 초과 건이 관리자 요약에 보인다
- AI 답마다 근거 조항이 보이고, 다른 화주사 문서가 섞이지 않으며, 지침서·계약서가 다르면 판단 대신 확인을 안내한다
- 화주사 계정으로 다른 화주사 자료, 규칙 질문, 문서를 요청하면 서버가 거부한다
